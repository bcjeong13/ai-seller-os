# 상품 등록 자동화 — 의견 요청

> 이 문서를 GPT에게 그대로 주고 의견을 받으려고 합니다.
> 아래 「묻고 싶은 것」의 5개 질문에 답해주세요.

---

## 0. 나는 누구인가 (전제)

- 1인 초보 셀러. **무재고 위탁판매**: 고객 주문 → 도매처(도매꾹 등)에 발주 → 도매처가 고객에게 직배송.
- 국내 도매 → 국내 마켓(네이버·쿠팡·11번가·G마켓·옥션). **해외 소싱 없음.**
- 상용 툴(윈들리·퍼센티 등)을 쓰지 않고, **직접 만든 앱**으로 전부 처리하려 함.
- 앱 이름: AI Seller OS.

## 1. 지금 앱이 어디까지 하는가

**기술 구조 (중요)**

| 항목 | 현재 |
|---|---|
| 프론트 | TypeScript + React 18 + Vite |
| 저장소 | **localStorage 뿐. 서버·백엔드·DB 없음** |
| 수집 | Chrome/Edge MV3 확장 (`chrome.scripting.executeScript`) |
| 앱 ⇄ 확장 | **클립보드 텍스트 블록**으로 주고받음 (`##AISOS##` 등) |
| 계산 | 전부 코드로 결정론적 계산. AI는 설명문만 |

**소싱 → 등록 흐름 (현재)**

1. 확장이 도매꾹 검색 목록에서 후보 100개를 담음 → 앱이 1차 필터(묶음·배송비·최소구매수량·위험군)
2. 확장이 남은 후보의 네이버 쇼핑 시세를 자동 조사 → 앱이 "팔 자리가 있는가"로 거름
3. 살아남은 것만 상세 수집(공급가·배송비·옵션·스펙·반품정책) → 손익 계산 → 🟢🟡🔴 판정
4. **등록할 내용 생성** ← 지금 문제 삼는 지점
5. 등록은 사람이 손으로. 앱은 "어디까지 올렸나"만 체크로 추적

**4번이 지금 만들어내는 것 (실제 출력)**

```
[상품명 후보]  차량용 무선 핸드폰 거치대 (14자)

[키워드]  #차량용 #무선 #핸드폰 #거치대 #블랙 #화이트 #실버

[설명문 — 순수 텍스트]
[🎨 옵션 안내]
· 블랙  · 화이트  · 실버 (+500원)

[🚚 배송 안내]
· 주문 후 영업일 기준 평균 2~3일 이내 발송됩니다.
· 도서산간 지역은 배송비·기간이 추가될 수 있습니다.

[🔁 교환/반품 안내]
· 전자상거래법에 따라 상품 수령 후 7일 이내 청약철회가 가능합니다.
· 단순변심 반품 시 왕복 배송비는 구매자 부담입니다.

[❓ 자주 묻는 질문]
Q. 배송은 얼마나 걸리나요? / Q. 반품이 가능한가요? / Q. 어떤 옵션이 있나요?
```

- 원본에 없는 효능·기능은 만들지 않음 (과장 문구 차단 목록 있음)
- **판매자 전용 정보(도매처 재고·매입가·공급사명·제조사)는 자동으로 제거**하고 무엇을 뺐는지 경고로 알림

## 2. 무엇이 불만인가

**(가) 등록이 여전히 100% 손이다.**
마켓 5곳 × 상품 10개 = 50번을 사람이 복사·붙여넣기 한다. 상품이 100개가 되면 무너진다.

**(나) "상세페이지"라고 부르는 게 사실은 안내문 덩어리다.**
지금 나오는 건 배송·반품·FAQ 같은 **공통 안내**뿐이다.
실제 마켓 상세페이지는 이런 구조인데:

```
[대표 이미지]
[후킹 문구 — 이 상품을 왜 사야 하는가]
[핵심 특징 3~5개 + 각각 이미지]
[상세 스펙 표]
[사용 방법 / 사용 씬]
[배송·반품 안내]   ← 지금 여기만 만들고 있음
[FAQ]              ← 여기도
```

이미지는 확장으로 도매처에서 받아 사람이 올린다 치더라도,
**글(카피)은 앱이 훨씬 더 많이 만들어줘야 하는 것 아닌가?**

## 3. 자동화 후보 (내가 아는 선에서)

### A. 마켓 오픈API로 직접 등록

- 네이버 커머스API, 쿠팡 오픈API, 11번가 오픈API, ESM(G마켓·옥션) API가 **존재하는 것으로 안다.**
- 걸림돌:
  - **사업자등록증 + API 신청/승인**이 필요하다 (마켓마다 조건·심사가 다름)
  - **API 키/시크릿을 브라우저에 둘 수 없다.** 지금 앱은 백엔드가 없어서 키를 숨길 데가 없다.
    → 자동화하려면 **서버나 로컬 실행기(Node/Electron)를 새로 만들어야 한다.**
  - 마켓마다 카테고리 코드·필수 속성·이미지 규격이 전부 달라 매핑이 큰 일이다.

### B. 마켓 「엑셀 대량등록」 템플릿 자동 생성

- 마켓들이 공식적으로 제공하는 기능이다. 승인도, 서버도, API 키도 필요 없다.
- 앱이 마켓별 양식에 맞춘 **엑셀 파일을 만들어 다운로드**해주면, 사람은 그 파일 하나를 업로드하면 끝.
- 상품 50개를 한 번에 올릴 수 있다.
- 걸림돌: 양식이 마켓마다 다르고 **수시로 바뀐다.** 카테고리 코드는 여전히 사람이 골라야 할 수 있다.

### C. 확장으로 판매자센터 입력폼 자동 채우기

- 확장은 이미 `<all_urls>` 권한과 `executeScript`를 갖고 있다.
- 사용자가 **본인 계정으로 로그인한 판매자센터 등록 화면**에서 버튼을 누르면, 상품명·가격·설명·옵션을 폼에 채워 넣는다. **저장 버튼은 사람이 누른다.**
- 걸림돌: 마켓이 화면을 바꾸면 깨진다. 마켓 이용약관상 허용되는지 확인이 필요하다.

### D. 상세페이지를 HTML로 생성 (당장 가능)

- 마켓 에디터 대부분이 **HTML 소스 입력**을 지원한다.
- 지금의 순수 텍스트 대신, **모바일 폭 기준 인라인 스타일 HTML**을 만들어 통째로 붙여넣게 한다.
- 이미지가 들어갈 자리를 표시해두고, 사람은 이미지만 끼워 넣는다.
- 승인도 서버도 필요 없다. **오늘 바로 만들 수 있는 유일한 선택지.**

## 4. 절대 어길 수 없는 제약 (기존에 정한 것)

1. **로그인 우회, CAPTCHA 우회, 탐지 회피, 24시간 서버 크롤링을 만들지 않는다.**
   사용자가 로그인한 정상 브라우저 세션에서, 사용자가 버튼을 눌렀을 때만 동작한다.
2. **개인정보(배송지·연락처)는 localStorage에만.** GitHub·외부 전송 금지.
3. **AI가 확정하지 않는다.** 판매 가능 여부, KC 인증 필요 여부, 법적 문제 없음, 매출 보장을 단정하지 않는다.
4. **점수 시스템 금지.** 87점 같은 숫자를 만들지 않는다. 3단계(🟢🟡🔴) + 근거만.
5. **읽지 못하면 정상으로 처리하지 않는다.** "확인 실패"로 남긴다.
6. **원본에 없는 효능·기능을 지어내지 않는다.** 과장 광고는 반품·신고로 돌아온다.
7. 계산은 코드가, 서술은 AI가. 섞지 않는다.

## 5. 묻고 싶은 것

**Q1. 순서.**
A(오픈API) / B(엑셀 대량등록) / C(확장 폼 자동채우기) / D(HTML 상세페이지) 중
**1인 초보 셀러가 가장 먼저 얻어야 할 것은 무엇이고, 그 이유는?**
그리고 **끝내 만들지 말아야 할 것**이 있다면 무엇인가?

**Q2. 사실 확인.**
2026년 현재 기준으로,

- 네이버 커머스API / 쿠팡 오픈API / 11번가 / ESM 의 **상품 등록 API가 개인·소규모 셀러에게 실제로 열려 있는가?** 신청 조건과 승인 난이도는?
- 각 마켓이 **엑셀 대량등록**을 지금도 제공하는가? 개당 몇 개까지?
- **확장으로 판매자센터 폼을 자동 입력하는 것**이 각 마켓 이용약관상 문제가 되는가?

*(모르면 "확실하지 않다"고 답해달라. 추측을 사실처럼 쓰지 말 것.)*

**Q3. 상세페이지 카피를 어디까지 자동 생성해도 되는가.**
도매처 상세페이지에서 얻을 수 있는 건 상품명·옵션·스펙(소재·사이즈·용량)·이미지 정도다.
이걸로 **후킹 문구 / 핵심 특징 / 사용 씬**까지 만들면 어디부터가 "지어낸 것"인가?
**허용선과 금지선을 구체적인 문장 예시로** 그어달라.
(예: "가볍습니다" ← 스펙에 무게가 있으면 OK? / "차박에 딱입니다" ← 용도 추정은 OK?)

**Q4. 위탁판매 특유의 함정.**
같은 도매 상품을 수백 명이 똑같이 올린다. 도매처 상세 이미지와 문구를 그대로 쓰면
**중복 콘텐츠로 노출이 죽거나, 이미지 저작권 문제가 생기거나, 마켓 제재를 받을 수 있는가?**
그렇다면 앱이 무엇을 자동으로 바꿔줘야 하는가?

**Q5. 다음 한 걸음.**
위를 다 고려해서, **다음에 만들 기능 딱 하나**를 고른다면? 그 이유와 함께.
그리고 그 기능의 **입력 → 처리 → 출력**을 구체적으로 적어달라.

Product {
  name, supplierName, sourceUrl
  cost:  { supplyPriceKrw, shippingKrw, minOrderQty }
  price: { listPriceKrw, discountKrw, buyerPaidKrw, buyerShippingKrw }
  options: { name, addPriceKrw, supplyPriceKrw, enabled }[]
