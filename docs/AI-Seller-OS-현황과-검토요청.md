## 0. 나는 누구이고 무엇을 만들고 있나

- **1인 초보 셀러.** 무재고 위탁판매: 고객 주문 → 도매처(도매꾹)에 발주 → 도매처가 고객에게 직배송.
- 국내 도매 → 국내 마켓(네이버·쿠팡·11번가·G마켓·옥션). **해외 소싱 없음.**
- 윈들리·퍼센티 같은 상용 툴을 쓰지 않고 **직접 만든 앱 하나로** 전부 처리한다.
- 이 앱의 목적은 "많이 파는 것"이 아니라 **"손해 보지 않는 것"** 이다.

### 기술 구조

| 항목 | 현재 |
|---|---|
| 프론트 | TypeScript + React 18 + Vite |
| 저장소 | **localStorage 뿐. 서버·백엔드·DB 없음** |
| 수집 | Chrome/Edge MV3 확장 (`chrome.scripting.executeScript`) v0.7.1 |
| 앱 ⇄ 확장 | **클립보드 텍스트 블록** (`##AISOS##`, `##AISOS-LIST##` 등) |

| 규모 | 도메인 모듈 27개 · 화면 13개 · 테스트 265개 |

## 1. 절대 어기지 않는 원칙 (지금까지 정한 것)

1. **배송비는 무조건 선불(주문시결제).** 착불이면 택배기사가 고객에게 배송비를 요구 → 환불·별점 1점.
2. **크롤링 금지선** — 로그인 우회, CAPTCHA 우회, 탐지 회피, 24시간 서버 크롤링을 만들지 않는다.
   사용자가 로그인한 정상 브라우저에서, **사용자가 버튼을 눌렀을 때만** 읽는다.
3. **개인정보는 localStorage에만.** 화면은 기본 마스킹(`홍*동`, `010-****-5678`), 배송완료 90일 후 자동 파기,
   이벤트 로그에 원문 금지, 백업 시 경고.
4. **AI가 확정하지 않는다.** 판매 가능 여부·KC 인증 필요 여부·법적 문제 없음·매출 보장을 단정하지 않는다.
5. **점수 시스템 금지.** 87점 같은 숫자를 화면에 만들지 않는다. 3단계(🟢🟡🔴) + 근거만. 정렬용 내부 rank만 허용.
6. **읽지 못하면 정상으로 처리하지 않는다.** "확인 실패"로 남긴다.
7. **값이 없는 것과 나쁜 것은 다르다.** 판매가를 아직 안 정한 것을 "손해"로 계산하지 않는다.
8. **원본에 없는 효능·기능을 지어내지 않는다.** 과장 광고는 반품·신고로 돌아온다.
9. **체크박스를 늘어놓지 않는다.** 초보자는 전부 체크하고 넘어간다.
   **코드가 볼 수 있는 것은 코드가 판정하고, 사람에게는 코드가 볼 수 없는 것만 묻는다.**

## 3. 최근에 만든 것 (이번 라운드)

### 상품정보제공고시 (`notice.ts`)
- 10개 분류(식품·화장품·유아·전기·가구·의류·신발·가방·주방·기타)마다 요구 항목이 다르다.
- **도매처 스펙에서 채울 수 있는 만큼 자동으로 채우고 나머지만 묻는다.**
- **A/S 책임자 연락처는 자동으로 채우지 않는다** — 도매처 번호가 고객에게 나가면 클레임이 도매처로 간다.
- 못 채운 게 3개 넘으면 🔴 — 등록이 거부될 수 있다고 미리 알린다.

### 판매자 반품정책을 공급처 정책과 분리 (`sellerPolicy.ts`)
- 도매처가 **나에게** 해주는 것과 내가 **고객에게** 약속하는 것은 다르다.
- 간극을 금액으로 보여준다: *"도매처가 5,000원 받는데 고객에게 3,000원만 받습니다 → 반품 1건마다 2,000원 내 손해"*
- 청약철회는 법정 최소 7일 밑으로 못 내려간다. 도매처 원문을 고객 안내문에 그대로 옮기지 않는다.

### 상세페이지 HTML (`listingHtml.ts`)
- 마켓 에디터가 `<style>` 태그를 지우므로 **전부 인라인 스타일**.
- **중복 콘텐츠 방어**: 상품마다 소제목·골격을 다르게 뽑는다(상품명 시드 — 같은 상품은 항상 같은 결과).
- 미리보기를 📱휴대폰(390px) / 🖥️PC / HTML 세 가지로 본다.
- 스펙에 있는 사실만 쓴다. **"400g의 가벼운 제품"의 '가벼운'도 안 쓴다** — 가벼운지는 우리가 판단할 일이 아니다.

### 마켓별 변환 계층 (`marketplaceProduct.ts`)
- **저장하지 않고 매번 계산한다.** 상품을 고쳤는데 마켓용 데이터가 옛날 것으로 남는 사고를 막는다.
- 마켓별 제한값은 한 곳(RULES)에만 둔다. 나중에 엑셀·API로 가도 **출구만 바뀌고 변환 규칙은 그대로 쓴다.**

### 수집 내용 합치기 (`collectMerge.ts`)
- 소싱센터에서 담은 초안에 확장 수집 결과를 채워 넣는다. 같은 상품을 두 개 만들지 않는다.
- **반영 전에 무엇이 바뀌는지 표로 보여준다.** 손익에 영향 주는 변화는 따로 표시.
- 내가 정한 판매가·꺼둔 옵션·고시정보는 건드리지 않는다.
- 다른 상품 번호를 붙여넣으면 경고한다.

## 4. 실제로 잡은 버그들 (설계 판단의 근거)

| 증상 | 원인 | 교훈 |
|---|---|---|

## 6. 묻고 싶은 것

### Q1. 지금 순서가 맞나
`상세페이지 HTML(완료) → 엑셀 대량등록 → 확장 폼 자동입력 → 오픈API`
이 순서가 1인 초보 셀러에게 맞는가? 바꿔야 한다면 무엇을 먼저?

### Q2. 사실 확인 (모르면 모른다고 답해주세요)
- 네이버·쿠팡·11번가·ESM의 **엑셀 대량등록**을 지금도 제공하는가? 한 번에 몇 개까지?
- **확장으로 판매자센터 폼을 자동 입력**하는 것이 각 마켓 이용약관상 문제가 되는가?
- 개인·신규 셀러가 **오픈API 사용 승인**을 실제로 받을 수 있는가? 조건은?

### Q3. 중복 콘텐츠
같은 도매 상품을 수백 명이 올린다. 도매처 이미지·문구를 그대로 쓰면
**중복 콘텐츠로 노출이 죽거나, 저작권 문제가 생기거나, 마켓 제재를 받는가?**
우리는 상품마다 소제목·골격을 다르게 뽑는 정도로 대응했는데 **그걸로 충분한가?**

### Q4. 원본에 없는 것을 쓰는 경계
스펙에 "중량 400g"이 있을 때 —
- `"중량 400g"` (지금 우리 방식)
- `"400g의 가벼운 제품입니다"`
- `"한 손으로 들 수 있습니다"`
어디까지가 허용이고 어디부터가 지어낸 것인가? **구체적인 문장 예시로** 선을 그어달라.

### Q5. ★ 신상품·이슈 레이더 — 이번의 핵심 질문

**하고 싶은 것**: 매일 아침 *"어제 없던 것 / 지금 뜨는 것"* 을 목록이나 배너로 보고 싶다.
새로 나온 상품, 갑자기 검색이 느는 키워드, 없던 유형의 제품.

**제약**: 24시간 서버 크롤링은 만들지 않기로 했다. 사용자가 로그인한 브라우저에서
버튼을 눌렀을 때만 읽는다. 서버가 없으니 데이터는 localStorage에 쌓인다.

묻고 싶은 것:

1. **어디를 봐야 하는가?** 국내 위탁판매 기준으로 "신상품·이슈"를 알 수 있는
   **공개된** 출처는 어디인가? (도매꾹 신상품 목록 / 네이버 데이터랩 쇼핑인사이트 /
   네이버쇼핑 베스트 / 쿠팡 랭킹 / 그 외) 각각 **로그인 없이 볼 수 있는가?**
2. **어떻게 "새것"을 판별하는가?** 서버 없이 매일 스냅샷을 localStorage에 쌓아
   "어제 목록에 없던 것"을 신규로 보는 방식이 현실적인가? 며칠 치가 필요한가?
3. **신상품을 쫓는 게 초보자에게 좋은 전략인가?** 나는 재미있어 보이는데,
   검증 안 된 신상품은 반품·CS 위험이 크지 않나? **솔직하게 답해달라.**
   좋다면 어떤 조건에서, 나쁘다면 대신 무엇을 봐야 하나?
4. **"이슈"를 무엇으로 정의해야 하나?** 검색 급상승? 신규 등록 급증? 가격 급락?
   초보자가 실제로 행동할 수 있는 신호는 무엇인가?
5. 이걸 **배너로 띄우는 게 맞나, 별도 목록이 맞나?** 매일 아침 새 상품을 들이대면
   기존 상품 관리를 소홀히 하게 되지 않을까?

### Q6. 다음 한 걸음
위를 다 고려해서 **다음에 만들 기능 딱 하나**를 고른다면? 그 이유와 함께,
**입력 → 처리 → 출력**을 구체적으로 적어달라.

## 부록 — 데이터 구조

